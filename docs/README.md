# Job Parser for arbeidsplassen.nav.no

## Опис проєкту

Автоматичний парсер вакансій з норвезької сайту arbeidsplassen.nav.no для регіону VESTLAND/SUNNFJORD. Проект розгорнутий на GitHub Actions і працює повністю автоматично, надсилаючи сповіщення в Telegram при появі нових вакансій.

**🚀 Статус:** **АКТИВНИЙ** - працює на GitHub Actions, надсилає сповіщення в Telegram 2 рази на день.

## Цілі

- ✅ Автоматичний моніторинг сторінки вакансій (GitHub Actions)
- ✅ Виявлення нових або оновлених оголошень (порівняння зі станом)
- ✅ Інформування користувача через Telegram з LLM-аналізом
- ✅ Збереження стану між запусками (в git)
- ✅ Надійна обробка помилок та збереження стану навіть при збоях

## Архітектура

### Структура файлів:
```
demo/
├── main.py                    # Головний скрипт з логікою перевірки
├── src/                       # Python модулі
│   ├── config.py             # Конфігурація (URL, ключі, розклад)
│   ├── fetcher.py            # Завантаження HTML сторінки

│   ├── storage.py            # Збереження та порівняння стану

├── docs/                     # Документація
├── data/state.json           # Стан вакансій (JSON)
└── .github/workflows/        # GitHub Actions конфігурація
```

### Детальна логіка роботи

#### 1. GitHub Actions Scheduler
- Автоматичні запуски: 6:00 UTC (8:00 Oslo) та 18:00 UTC (20:00 Oslo)
- Кожен запуск виконує `python main.py`
- Після виконання перевіряє зміни в `data/state.json` і комітить їх назад у репозиторій

#### 2. Головний процес (main.py)
```
check_jobs():
  - Завантажити HTML сторінки (fetcher)
  - Розпарсити вакансії (parser) -> список dict з id, title, etc.
  - Завантажити попередній стан (storage.load_previous_state)
  - Порівняти поточний стан з попереднім (storage.find_changed_jobs)
    -> added: нові вакансії
    -> modified: оновлені вакансії
    -> removed: видалені вакансії
  - Якщо є added або modified:
    - Для кожної нової/оновленої вакансії:
      - Отримати повний опис (parser.get_full_job_description)
      - Проаналізувати через LLM (llm.summarize_job)
      - Надіслати повідомлення в Telegram (notifier.send_telegram_message)
  - Зберегти новий стан (storage.save_state) - завжди, навіть при помилках
```

#### 3. Storage (storage.py)
- **Збереження стану:** `data/state.json` містить dict з id вакансії як ключ, і повними даними як значення
- **Порівняння:** 
  - Поточний стан: нормалізує всі вакансії, фільтрує ті з id
  - Порівнює id поточних з попередніми
  - Знаходить додані, змінені (якщо дані змінилися), видалені
- **Надійність:** Використовує тимчасовий файл для атомарного запису, щоб уникнути пошкодження при збоях

#### 4. Parser (parser.py)
- Парсить HTML з BeautifulSoup
- Знаходить блоки вакансій (article або a[href*='/stillinger/'])
- Для кожної витягує: title, company, location, published, summary, url
- Нормалізує id з url (без query)
- Для повного опису: завантажує окрему сторінку вакансії, витягує текст

#### 5. LLM (llm.py)
- Використовує Groq API (через openai-сумісний інтерфейс)
- Аналізує повний опис вакансії за фіксованим prompt українською
- Витягує: спеціалізація, обов'язки, навички, вимоги
- Fallback: якщо API недоступне, повертає короткий текст з полів вакансії

#### 6. Notifier (notifier.py)
- Надсилає HTML-повідомлення в Telegram
- Формат: заголовок, компанія/місце, LLM-аналіз, посилання

- **6:00 UTC** (8:00 ранку Oslo) - ранкова перевірка
- **18:00 UTC** (20:00 вечора Oslo) - вечірня перевірка

Кожен запуск:
1. Парсить поточні вакансії (5-10 вакансій)
2. Порівнює з збереженим станом (3-10 вакансій)
3. Надсилає тільки нові/оновлені вакансії
4. Оновлює стан у git

## Поточні помилки та проблеми

### 1. Збереження стану на GitHub
- **Симптом:** `data/state.json` не оновлюється після GitHub Actions run
- **Причина:** Локально файл змінюється, але GitHub Actions не комітить, бо diff не знаходить змін (через баг у save_state)
- **Виправлення:** Використовувати `os.replace` замість `Path.replace` для надійного перезапису на Windows
- **Статус:** Виправлено в коді

### 2. LLM не працює
- **Симптом:** Повідомлення приходять без аналізу, тільки заголовок і посилання
- **Причина:** Відсутність модуля `openai` у `requirements.txt` (хоча Groq використовує openai API)
- **Виправлення:** Додати `openai>=1.0` до залежностей
- **Статус:** Виправлено

### 3. Порівняння стану
- **Симптом:** Іноді вакансії не визнаються як нові, хоча вони нові
- **Причина:** id вакансії може змінюватися, або парсер пропускає деякі вакансії без id
- **Виправлення:** Перевірити нормалізацію id та фільтрацію вакансій
- **Статус:** Потрібно тестування

### 4. GitHub Actions обмеження
- **Симптом:** Іноді Actions падає через timeout або rate limits
- **Причина:** GitHub Actions має обмеження на тривалість (6 годин) та мережеві запити
- **Виправлення:** Оптимізувати код, додати retries
- **Статус:** Моніторинг

## Налаштування

### Secrets на GitHub:
- `GROQ_API_KEY` - API ключ від Groq (https://console.groq.com)
- `TELEGRAM_BOT_TOKEN` - токен Telegram бота (@BotFather)
- `TELEGRAM_CHAT_ID` - ID чату для сповіщень (@userinfobot)

### Локальний запуск:
```bash
pip install -r requirements.txt
cp .env.example .env  # заповни ключі
python main.py test      # тестовий запуск (без збереження)
python main.py           # один запуск і вихід (GitHub Actions)
python main.py schedule  # запуск з APScheduler (локально)
```

## LLM-обробка

LLM може робити одне з наступного:

- короткий опис вакансії
- оцінка релевантності до ключового слова "ingeniør"
- класифікація за типом роботи

## Розгортання

- Запускати на сервері або Raspberry Pi
- Налаштувати `cron` / `systemd timer` або тривалий скрипт з `APScheduler`
- Зберігати стан у локальному файлі `data/state.json` або `sqlite`

## Як запустити

1. Скопіюйте файл `.env.example` у `.env` та заповніть ключі API і Telegram-токен.
2. Встановіть залежності:
   - `python -m pip install -r requirements.txt`
3. Запустіть проєкт:
   - `python main.py test` — тестовий режим (виводить вакансії, без збереження)
   - `python main.py` — один запуск і вихід (для GitHub Actions)
   - `python main.py schedule` — безперервний запуск з APScheduler (локально: 10:00/16:00 Oslo)
4. На GitHub Actions запуски виконуються автоматично о 6:00 та 18:00 UTC (8:00 і 20:00 Oslo).

## Налаштування LLM

Проєкт використовує **Groq API** для LLM-аналізу вакансій (через openai-сумісний інтерфейс).

- Отримай ключ на https://console.groq.com
- В `.env` додай `GROQ_API_KEY=твій_ключ`

Якщо ключ відсутній, використовується fallback (без аналізу).

## Тестування

Для тестування функціональності без надсилання повідомлень:

- `python main.py test` — тестовий режим, виводить знайдені вакансії
- `python -m src.test` — повний тест парсера
- `python -m src.test fetcher` — тест тільки завантаження сторінки
- `python -m src.test storage` — тест збереження/завантаження стану
