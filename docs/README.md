# Job Parser for arbeidsplassen.nav.no

## Опис проєкту

Невеликий Python-проєкт, який двічі на день перевіряє сторінку вакансій на arbeidsplassen.nav.no для регіону VESTLAND/SUNNFJORD. Якщо з'являються нові вакансії, система надсилає пуш-повідомлення в Telegram через бота.

## Цілі

- Автоматичний моніторинг сторінки вакансій
- Виявлення нових оголошень
- Інформування користувача через Telegram
- Аналіз опису вакансії через LLM для покращення повідомлення

## Архітектура

1. `scheduler`
   - Двічі на день (о 10:00 та 16:00) запускає перевірку
   - Може використовувати `APScheduler` або стандартний `schedule`

2. `fetcher`
   - Завантажує HTML сторінки
   - Використовує `requests` та `BeautifulSoup`

3. `parser`
   - Парсить список вакансій
   - Витягує заголовок, місце, компанію, дату публікації, посилання

4. `diff` / `storage`
   - Зберігає останній стан вакансій
   - Порівнює поточний результат із попереднім
   - Визначає нові вакансії

5. `notifier`
   - Відправляє повідомлення в Telegram через бот
   - Може надсилати короткий опис + посилання

6. `llm_enhancer`
   - Опрацьовує опис вакансії через LLM
   - Формує короткий підсумок або класифікацію

## Технологічний стек

- Python 3.11+
- requests
- beautifulsoup4
- APScheduler або schedule
- python-telegram-bot або aiogram
- optional: OpenAI / local LLM interface
- optional: sqlite3 або JSON для збереження стану

## Компоненти та файлова структура

Пропонована структура:

- `README.md` — ця документація
- `requirements.txt` — список залежностей
- `config.py` — налаштування Telegram, URL, розклад
- `main.py` — точка входу
- `fetcher.py` — завантаження сторінки
- `parser.py` — витяг даних вакансій
- `storage.py` — збереження / порівняння стану
- `notifier.py` — відправка повідомлень
- `llm.py` — обробка через LLM

## Функціональні вимоги

- Перевірка сторінки за розкладом 10:00 та 16:00
- Надсилання повідомлення лише при появі нових вакансій
- Збереження останнього відомого стану вакансій
- Можливість додати LLM для аналізу опису вакансій
- Підтримка Telegram-бота

## Приклад робочого сценарію

1. `scheduler` запускає `main.py`
2. `fetcher` отримує HTML
3. `parser` розбирає вакансії
4. `storage` порівнює зі збереженим станом (data/state.json)
5. Якщо є нові вакансії:
   - `llm` аналізує опис
   - `notifier` надсилає повідомлення в Telegram
6. Оновлений стан зберігається (state.json завжди містить поточний стан вакансій)

## Логіка порівняння

- `state.json` зберігає поточний стан вакансій після кожного успішного запуску
- При наступному запуску порівнюється поточний список зі збереженим
- Нові вакансії — це ті, що є зараз на сайті, але не було в минулому стані
- Якщо видалити вакансію з `state.json`, вона буде знайдена як нова тільки якщо вона ще присутня на сайті

## Telegram-повідомлення

У повідомленні можна вказати:

- назву вакансії
- компанію / місце
- короткий LLM-резюме
- посилання на оголошення
- дату публікації

## LLM-обробка

LLM може робити одне з наступного:

- короткий опис вакансії
- оцінка релевантності до ключового слова "ingeniør"
- класифікація за типом роботи

## Розгортання

- Запускати на сервері або Raspberry Pi
- Налаштувати `cron` / `systemd timer` або тривалий скрипт з `APScheduler`
- Зберігати стан у локальному файлі `data/state.json` або `sqlite`

## Наступні кроки

1. Створити `requirements.txt` і налаштувати середовище
2. Реалізувати базовий `fetcher` + `parser`
3. Додати збереження стану та порівняння
4. Підключити Telegram-бота
5. За бажанням — інтегрувати LLM для аналізу опису вакансій

## Як запустити

1. Скопіюйте файл `.env.example` у `.env` та додайте свій Telegram токен і chat ID.
2. Встановіть залежності:
   - `python -m pip install -r requirements.txt`
3. Запустіть проєкт:
   - `python main.py`
4. Перевірка виконається одразу при старті, а потім за розкладом 10:00 та 16:00.

## Налаштування LLM

Проєкт підтримує два провайдери LLM:

- **Groq** (рекомендовано): швидкий, безкоштовний ліміт
  - Отримай ключ на https://groq.com
  - В `.env` додай `GROQ_API_KEY=твій_ключ` і `LLM_PROVIDER=groq`

- **OpenAI**: GPT моделі
  - Отримай ключ на https://platform.openai.com
  - В `.env` додай `OPENAI_API_KEY=твій_ключ` і `LLM_PROVIDER=openai`

Якщо ключ відсутній, використовується fallback (без аналізу).

## Тестування

Для тестування функціональності без надсилання повідомлень:

- `python main.py test` — тестовий режим, виводить знайдені вакансії
- `python test.py` — повний тест парсера
- `python test.py fetcher` — тест тільки завантаження сторінки
- `python test.py storage` — тест збереження/завантаження стану
- `python test.py parser` — тест парсера та порівняння зі станом
