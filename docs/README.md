# Job Parser for arbeidsplassen.nav.no

## Опис проєкту

Автоматичний парсер вакансій з норвезької сайту arbeidsplassen.nav.no для регіону VESTLAND/SUNNFJORD. Проект розгорнутий на GitHub Actions і працює повністю автоматично.

**🚀 Статус:** **АКТИВНИЙ** - працює на GitHub Actions, надсилає сповіщення в Telegram 2 рази на день.

## Цілі

- ✅ Автоматичний моніторинг сторінки вакансій (GitHub Actions)
- ✅ Виявлення нових оголошень (порівняння зі станом)
- ✅ Інформування користувача через Telegram
- ✅ Аналіз опису вакансії через Groq LLM
- ✅ Збереження стану між запусками (в git)

## Архітектура

### Структура файлів:
```
demo/
├── main.py                    # Головний скрипт
├── src/                       # Python модулі
│   ├── config.py             # Конфігурація
│   ├── fetcher.py            # Завантаження HTML
│   ├── parser.py             # Парсинг вакансій
│   ├── storage.py            # Збереження стану
│   ├── llm.py               # Groq LLM аналіз
│   └── notifier.py          # Telegram сповіщення
├── docs/                     # Документація
├── data/state.json           # Стан вакансій
└── .github/workflows/        # GitHub Actions
```

### Компоненти:

1. **GitHub Actions Scheduler**
   - Автоматичні запуски: 6:00 UTC (8:00 Oslo) та 18:00 UTC (20:00 Oslo)
   - Повністю безсерверне рішення

2. **Fetcher**
   - Завантажує HTML сторінки з requests
   - Використовує User-Agent для обходу блокувань

3. **Parser**
   - Парсить вакансії з BeautifulSoup
   - Витягує: заголовок, компанія, місце, дата, посилання
   - Отримує повний опис з окремих сторінок

4. **Storage**
   - Зберігає стан в `data/state.json`
   - Порівнює поточні вакансії з попередніми
   - Відстежує відправлені вакансії

5. **LLM (Groq)**
   - Аналізує опис вакансії
   - Витягує спеціалізацію, навички, вимоги
   - Відповідає українською мовою

6. **Notifier**
   - Надсилає повідомлення в Telegram
   - Використовує HTML форматування

## Технологічний стек

- **Python 3.11+**
- **GitHub Actions** - для автоматичних запусків
- **Requests + BeautifulSoup** - для веб-скрапінгу
- **Groq API** - для LLM аналізу
- **Python-telegram-bot** - для сповіщень
- **JSON** - для збереження стану

## Розклад роботи

- **6:00 UTC** (8:00 ранку Oslo) - ранкова перевірка
- **18:00 UTC** (20:00 вечора Oslo) - вечірня перевірка

Кожен запуск:
1. Парсить поточні вакансії
2. Порівнює з збереженим станом
3. Надсилає тільки нові вакансії
4. Оновлює стан

## Налаштування

### Secrets на GitHub:
- `GROQ_API_KEY` - API ключ від Groq
- `TELEGRAM_BOT_TOKEN` - токен Telegram бота
- `TELEGRAM_CHAT_ID` - ID чату для сповіщень

### Локальний запуск:
```bash
pip install -r requirements.txt
cp .env.example .env  # заповни ключі
python main.py test   # тестовий запуск
```

- `llm.py` — обробка через LLM

## Функціональні вимоги

- Перевірка сторінки за розкладом 10:00 та 16:00
- Надсилання повідомлення лише при появі нових вакансій
- Збереження останнього відомого стану вакансій
- Можливість додати LLM для аналізу опису вакансій
- Підтримка Telegram-бота

## Приклад робочого сценарію

1. `scheduler` запускає `main.py`
2. `fetcher` отримує HTML
3. `parser` розбирає вакансії
4. `storage` порівнює зі збереженим станом (data/state.json)
5. Якщо є нові вакансії:
   - `llm` аналізує опис
   - `notifier` надсилає повідомлення в Telegram
6. Оновлений стан зберігається (state.json завжди містить поточний стан вакансій)

## Логіка порівняння

- `state.json` зберігає поточний стан вакансій після кожного успішного запуску
- При наступному запуску порівнюється поточний список зі збереженим
- Нові вакансії — це ті, що є зараз на сайті, але не було в минулому стані
- Якщо видалити вакансію з `state.json`, вона буде знайдена як нова тільки якщо вона ще присутня на сайті

## Telegram-повідомлення

У повідомленні можна вказати:

- назву вакансії
- компанію / місце
- короткий LLM-резюме
- посилання на оголошення
- дату публікації

## LLM-обробка

LLM може робити одне з наступного:

- короткий опис вакансії
- оцінка релевантності до ключового слова "ingeniør"
- класифікація за типом роботи

## Розгортання

- Запускати на сервері або Raspberry Pi
- Налаштувати `cron` / `systemd timer` або тривалий скрипт з `APScheduler`
- Зберігати стан у локальному файлі `data/state.json` або `sqlite`

## Наступні кроки

1. Створити `requirements.txt` і налаштувати середовище
2. Реалізувати базовий `fetcher` + `parser`
3. Додати збереження стану та порівняння
4. Підключити Telegram-бота
5. За бажанням — інтегрувати LLM для аналізу опису вакансій

## Як запустити

1. Скопіюйте файл `.env.example` у `.env` та додайте свій Telegram токен і chat ID.
2. Встановіть залежності:
   - `python -m pip install -r requirements.txt`
3. Запустіть проєкт:
   - `python main.py`
4. Перевірка виконається одразу при старті, а потім за розкладом 10:00 та 16:00.

## Налаштування LLM

Проєкт підтримує два провайдери LLM:

- **Groq** (рекомендовано): швидкий, безкоштовний ліміт
  - Отримай ключ на https://groq.com
  - В `.env` додай `GROQ_API_KEY=твій_ключ` і `LLM_PROVIDER=groq`

- **OpenAI**: GPT моделі
  - Отримай ключ на https://platform.openai.com
  - В `.env` додай `OPENAI_API_KEY=твій_ключ` і `LLM_PROVIDER=openai`

Якщо ключ відсутній, використовується fallback (без аналізу).
